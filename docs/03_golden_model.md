# 03 — Golden Model

## 1. Purpose

The Python behavioral model is the reference model for the digital backend of the Sigma-Delta ADC.

Its main purpose is to provide a deterministic numerical reference against which the Verilog RTL implementation can be verified.

The model represents the signal-processing chain used by the hardware:

```text
Input signal
     |
     v
Sigma-Delta modulation
     |
     | 1-bit bitstream
     v
CIC decimation
     |
     | /64
     v
FIR compensation
     |
     | /2
     v
Golden output
The golden output is subsequently used by the RTL testbench as the expected reference.

2. Python Model

The main behavioral model is:

model/sd_model.py

The model is written in Python and uses numerical signal-processing operations to reproduce the intended behavior of the digital backend.

The model is kept separate from the RTL implementation.

This separation is important because the reference should describe the expected numerical behavior independently of the hardware implementation details.

3. Signal Generation

The behavioral verification flow uses a deterministic input signal.

The model generates a test signal suitable for evaluating the Sigma-Delta conversion and the subsequent digital filtering chain.

The sampling frequency of the modulator is:

Fs_mod = 5.12 MHz

while the final output sampling frequency is:

Fs_out = 40 kHz

The test signal is selected inside the intended 20 kHz signal bandwidth.

4. Sigma-Delta Behavioral Model

The model implements a first-order Sigma-Delta modulator.

The modulator contains:

an integrator state;
a feedback signal;
a 1-bit quantizer.

The quantizer generates the one-bit stream used by the digital backend.

The binary representation is:

0 -> -1
1 -> +1

The resulting stream is stored as the reference Sigma-Delta bitstream.

Conceptually:

Analog / numerical input
          |
          v
     +-----------+
     | Integrator|
     +-----------+
          |
          v
     +-----------+
     | 1-bit     |
     | quantizer |
     +-----------+
          |
          v
      0 / 1 stream
5. Bitstream as Hardware Input

The generated Sigma-Delta bitstream represents the interface between the modulator and the digital backend.

The RTL therefore receives only one bit per modulator clock:

din = 0 or 1

The Python model does not need to reproduce the internal RTL implementation of the CIC or FIR.

Instead, it provides the expected numerical result for the complete digital processing chain.

6. CIC Reference Model

The Python model implements the CIC decimation stage corresponding to the RTL.

The CIC configuration is:

Number of stages = 3
Decimation       = 64
Differential delay = 1

The input bitstream is first interpreted in bipolar form:

0 -> -1
1 -> +1

The three integrator stages operate at the modulator sampling rate.

The signal is then decimated by 64.

The three comb stages operate after decimation.

The result is a multi-bit signal at:

5.12 MHz / 64 = 80 kHz
7. CIC Reference Function

The model contains a CIC decimation implementation used to generate the expected intermediate signal.

The processing can be summarized as:

1-bit stream
     |

     |
     v

     |
     v

     |

     |
     v

     |

     |

CIC output @ 80 kHz

The model and RTL therefore use the same fundamental CIC architecture.

8. FIR Compensation Reference

The CIC response introduces passband attenuation.

The Python flow therefore generates or applies a FIR compensation filter designed to compensate the CIC frequency response.

The FIR configuration is:

Number of taps = 15
Decimation     = 2
Coefficient width = 12 bit

The final output rate is:

80 kHz / 2 = 40 kHz

The FIR coefficients are quantized before being used by the RTL.

9. Fixed-Point FIR Coefficients

The coefficients used by the final RTL implementation are:

h[0]  = -3
h[1]  = -6
h[2]  = -14
h[3]  = -29
h[4]  = -51
h[5]  = -74
h[6]  = -93
h[7]  = 2047
h[8]  = -93
h[9]  = -74
h[10] = -51
h[11] = -29
h[12] = -14
h[13] = -6
h[14] = -3

The coefficients are represented using 12-bit signed fixed-point values in the RTL.

The symmetry is:

h[k] = h[14-k]

This property is exploited by the RTL implementation to reduce the number of multiplication terms.

10. Golden Output

The final output generated by the Python reference model is stored as the golden output.

The project uses:

output/golden_out.txt

as the numerical reference for RTL verification.

The expected output is represented using the same 16-bit output convention used by the RTL.

The golden output therefore represents the expected behavior of the complete digital backend.

11. Reference Files

During the development flow, the model generates or uses files including:

output/

├── fir_coef_hex.txt
├── golden_out.txt

Their purposes are:

These files form the interface between the Python reference flow and the RTL verification environment.

12. Golden Model and RTL Relationship

The verification methodology follows the principle:

             Python
                |
                v
        Golden reference
                |
                |
                v
        +---------------+
        | Verilog RTL   |
        +---------------+
                |
                v
          RTL output
                |
                v
        Numerical comparison

The Python model is therefore the reference, while the RTL is the implementation being tested.

A mismatch between the two indicates that the hardware implementation does not reproduce the expected signal-processing behavior.

13. Numerical Comparison

The RTL testbench compares the generated RTL output against the golden output.

The comparison uses the output samples produced after the complete CIC and FIR processing chain.

For the validated fixed-coefficient FIR implementation, the comparison produced:

Output samples compared: 4160
Maximum error:           0 LSB
Mismatches (>2 LSB):     0
Result:                  PASS

The result demonstrates that the RTL implementation reproduced the golden-model output for the tested dataset without numerical error.

14. Warm-Up and Transient Behavior

The filtering chain contains internal states and therefore has a startup transient.

The verification flow accounts for the initial transient before evaluating the steady-state output.

The model uses a warm-up interval related to the system oversampling ratio.

This prevents initialization effects from being interpreted as functional mismatches between the Python model and the RTL.

15. Frequency-Domain Verification

The model also supports frequency-domain evaluation of the processed signal.

A bin-aligned test tone can be selected with respect to the final output sampling frequency:

Fs_out = 40 kHz

and the number of generated output samples.

Using a bin-aligned tone reduces spectral leakage in FFT-based measurements and makes it easier to evaluate the behavior of the filtering chain.

The frequency-domain analysis is used as an additional characterization method, while the sample-by-sample comparison remains the primary RTL verification method.

17. Reproducibility

The golden-model approach provides a reproducible development flow.

Starting from the same model parameters and input conditions, the behavioral model generates the same reference bitstream and expected output.

The resulting files can then be supplied to the RTL testbench.

The intended reproducible sequence is:

Python model
     |
     +--> bitstream.txt
     |
     +--> FIR coefficients
     |
     +--> golden_out.txt
     |
     v
Verilog testbench
     |
     v
Icarus Verilog simulation
     |
     v
RTL vs golden comparison

This structure allows changes to the RTL to be validated without modifying the reference implementation.

18. Role in the ASIC Flow

The golden model is the first executable reference in the design flow.

It provides the expected behavior before synthesis and physical implementation.

The overall relationship is:

Specifications
      |
      v
Golden Model

      v

      |

      |

      |

A successful RTL-to-golden comparison therefore represents the functional verification milestone before proceeding to ASIC implementation.
